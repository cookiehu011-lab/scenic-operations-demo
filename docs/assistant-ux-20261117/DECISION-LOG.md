# 智能助手体验调整记录 · 2026-11-17

## 范围

仅调整智能助手的对话、历史记录、报告阅读与其本地数据匹配；不改动景区大屏和业务处理页面。

## 已确认诉求

- 回复内容要有明确的信息层级，辅助信息不能占据主要阅读空间。
- 对话宽度应便于阅读，避免内容横跨整个窗口。
- 移除无价值的“返回业务项”入口。
- 重整新对话首页与助手历史列表；历史列表仅显示问题标题和时间。
- 全面验收助手的问题、报告和按钮交互，发现问题直接修复。

## D-001 对话及报告布局

**问题**：对话占满可用宽度，回复层级不明显；长报告和来源材料会挤占对话阅读空间。

**候选方案**：

- A：保留左侧历史，主对话采用约 900px 阅读宽度；重点结论先展示，查询步骤与长材料可折叠；独立报告放在右侧阅读面板。
- B：对话与报告都继续使用全宽卡片流。
- C：为主对话常驻更多数据侧栏。

**评审视角及投票**：产品体验、对话信息架构、前端交互评审；A：3 票，B：0 票，C：0 票。

**反方审查**：窄栏会增加长表格的滚动距离。通过摘要优先、过程折叠、报告单独阅读和表格窄屏横向滚动控制影响。

**最终决议**：采用 A。交互结构参考常见聊天产品的左侧历史检索，以及长文档独立阅读区： [OpenAI 聊天记录搜索说明](https://help.openai.com/en/articles/10056348-how-do-i-search-my-chat-history-in-chatgpt)、[Anthropic Artifacts 说明](https://support.anthropic.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)。

**风险**：Low。布局均为可逆的助手样式调整。

## 假设

- 本体验版继续使用访客浏览器中的本地事项和报告数据；不表示数据来自实时景区系统，也不表示接入了在线大模型。
- 复杂的事件记录和报告适合默认收起，用户按需展开。
- 约 900px 的对话最大宽度兼顾桌面阅读与当前页面两侧栏；窄屏按单栏交互处理。
